# remote_transfer 审查（2026-10-16）

范围：`ToolCallCard.vue` / `style.css`、`orch_remote.go` 内的 Python 传输桥与流编排、`streamarchive`、`sshclient.RunStream`。结论：流式架构适合大文件；本次修复了越界写入、漏传和错误成功判定等问题。仍有下面列出的安全与可靠性边界，不能据此认定可以处理任意不可信远端或并发攻击者。

## 本次已修复

| 问题 | 修正 |
| --- | --- |
| 字段容器被网格当成列，标签和值粘连 | 每个字段独占一行，标签加冒号，固定标签列，长路径换行并保持值列对齐 |
| 归档条目可以写到请求目标的同级位置 | 上传检查条目必须属于指定目标；下载使用 `UnpackTarget` 限制归档根名称 |
| 已存在或先前归档条目创建的父目录链接可能使后续写入越界 | Python 拒绝符号链接父目录；Go 文件操作收口到 `os.Root`，并拒绝符号链接父目录 |
| 临时文件可预测且采用截断方式打开 | Python 使用 `mkstemp`；Go 使用 `O_EXCL` 排他创建；禁止覆盖时用硬链接发布，避免检查后覆盖竞态 |
| 用文件替换目录时，数据传完前就删除旧目录 | 文件内容完整写入临时文件后才处理目标；截断流保留旧文件或旧目录内容 |
| Python 下载吞掉读文件或遍历错误 | 读取、遍历失败会输出失败回执 |
| Python 默认硬链接去重、Go 接收端跳过硬链接，导致文件丢失 | 每个普通文件携带独立数据；不支持的 tar 类型明确报错 |
| 空目录没有归档根条目 | Go 打包输出根目录头，空目录正常往返 |
| 权限归一化把私有文件变得可公开读取 | 保留普通权限并去掉组/其他用户写权限；不导入 setuid/setgid/sticky 位 |
| 缺失成功回执仍可能报成功，统计没有核对 | 强制校验回执、非负完整统计，双向核对文件/目录数和字节数 |
| Python 流模式仍保留全部 tar 头及硬链接索引 | 每条处理后释放 tar 头，逐文件清除硬链接索引 |

## 仍然存在的边界

1. **高：主机指纹变化自动接受。** `refreshHostKeyAndRetry` 会替换已保存公钥并重连。攻击者若控制连接路径并成功伪装服务端，现有策略无法区分中间人与正常换钥。这是仓库明确采用的整体 SSH 策略，本次保留；需要严格服务端身份保证时应另行调整为指纹固定或人工核对。
2. **中：远端 Python 存在检查与使用间竞态。** Python 2.7 兼容路径使用路径检查和普通文件 API；检查后的父目录仍可能被另一个有写权限的进程替换。防护覆盖静态/归档内链接攻击，不构成对恶意并发本地进程的隔离。共享可写工作区需要基于目录句柄的操作或隔离账户。Go `os.Root` 限制目标父目录外的访问，但指定目标子树内的并发重定向也不能只靠一次名称检查作完整保证。
3. **中：没有传输空闲超时或总量配额。** SSH 有建连/握手超时，`RunStream` 运行阶段依赖调用方 context 取消；未在传输层设置空闲超时、总字节数或条目数预算。停滞的连接可能长时间占用任务；授权远端也可能持续输出并耗尽本地磁盘。建议配置化预算，避免用任意固定阈值破坏合法大文件传输。
4. **中：不是整目录事务。** 已完成文件会保留，后续条目失败时不回滚整个目录；目标类型切换也不是跨目录的事务。临时文件+重命名保护单个普通文件，不保证目录整体原子提交，也没有 fsync 级断电持久性承诺。
5. **兼容性：禁止覆盖时的排他发布依赖硬链接。** NTFS 和常见 Linux 本地文件系统支持；不支持硬链接的 FAT/exFAT、部分网络文件系统可能报错，保持失败而不退回可能覆盖的写法。需要这些文件系统时应设计明确的替代提交策略。
6. **兼容性：符号链接能力依赖平台权限。** 接收端不能创建链接时明确失败，不再静默漏掉；Python 2.7 仍需在真实 Linux 解释器上补测。

## 性能判断与本机测量

文件内容通过 `io.Pipe`、SSH 流和 tar 逐块传递，不整包转 Base64，也不整包驻留内存。Base64/zlib 只承载启动脚本和参数。复制缓冲约 64 KiB；目录时间戳集合、目录枚举仍随目录数量/宽度增长，因此不能把整个算法严格称为 O(1) 内存。

Windows / Python 3.13、本机 Python 下载桥→管道→Python 上传桥，临时目录内测量，包含两端解释器启动；逐文件 SHA-256 校验一致：

| 数据集 | 耗时 | 有效吞吐 |
| --- | --- | --- |
| 单文件 64 MiB | 0.900 秒 | 71.09 MiB/s |
| 1000 × 1 KiB 文件 | 2.259 秒 | 约 443 文件/秒 |

这组数字没有 SSH、真实网络和 Go 收发端开销，不能代表实际部署速度，也没有作为修改前后性能对照。小文件仍有逐文件创建、权限、时间戳和发布开销；大文件保留流式传输，不增加整包缓冲。
