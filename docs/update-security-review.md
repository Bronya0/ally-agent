# 自更新审查与修复记录

日期：2026-10-25。范围：下载、替换、备份清理与退出重启。

按本次要求保留现有更新架构，不引入签名密钥、自动重试、恢复状态机或后台安装器。

| 原检查项 | 本次处理 |
|---|---|
| 更新退出绕过保存队列 | 应用前、退出前均等待会话和设置写入结束；队列错误逐个消化，避免旧失败阻止更新或提前跳过其它保存；更新等待超时保留窗口 |
| 更新操作并发冲突 | 后端单一操作所有权；下载、安装、跳过共用文件锁；取消不再影响下次下载；安装期间禁止新任务注册 |
| macOS 替换时正式路径缺失 | 先完整复制并验证新 bundle，再用系统原子交换替换；旧 bundle 同时成为 `.bak` |
| Windows 资源备份过早丢弃 | 先备份全部待替换资源，再改 EXE；普通失败还原资源和 EXE；新界面初始化前保留备份 |
| 安装包只有 magic 检查 | 解析 PE/Mach-O，验证 CPU、执行类型；macOS 还检查执行权限、Bundle ID、目标版本及目录结构；DMG 校验 UDIF 字段和数据范围 |
| 下载后暂存内容变化 | 保存归档大小与 SHA-256 的本地收据，安装前复核；Windows 从复核过的归档重新解压 |
| 资源复制跟随父目录链接 | 安装和回滚通过 `os.Root` 约束路径；拒绝资源文件与父目录链接，避免写出安装目录 |
| 备份清理早于界面初始化 | 前端初始化完成后才通知后端清理；macOS 继续保留额外 10 秒及备份身份检查 |
| GitHub API 匿名限流 | Atom 取版本，固定文件名生成下载直链，不再查附件 API |

下载仍执行 TLS 证书校验，拒绝 HTTPS 降级重定向。哈希收据只用于检查下载完成后的本地一致性，不是发布者验签；它无法抵御能同时改写归档和收据的本地进程，也不能证明 GitHub Release 发布者的身份。

保留的边界：

- Windows 仍按原设计在退出后手动重新打开。资源是逐文件替换，不承诺断电后的整套安装自动恢复；备份保存在安装目录的 `.ally-update-backup`，旧 EXE 为 `Ally.exe.bak`。
- macOS 自动重新打开；启动失败会保留 `.bak` 供恢复，没有新增自动回滚监控。
- 不使用 API 时，Atom 无法辨认 GitHub 页面上的 prerelease 标志；本地拒绝带后缀的测试版标签，正式发布需继续使用纯数字版本标签。
- 新校验版本不能直接安装没有本地完整性收据的旧暂存文件，需要重新下载。

验证使用 `t.TempDir()`；未执行真实安装目录替换。覆盖直链与非法标签、收据篡改、伪造格式、资源回滚、父目录链接拦截、macOS bundle 原子交换，以及前端保存屏障。最终构建与测试结果见本次交付说明。
