# 按需界面检查

给文件树、侧栏这类界面留的较重检查：规模上去以后每帧还建不建多余的控件、键盘和点击的行为还对不对。**不进 `go test ./...`，也不进应用构建**，需要时手动跑。

```bash
python tests/explorer/run.py                      # 全部
python tests/explorer/run.py TestOnDemandExplorerTreeScale   # 只跑经规模那条
```

## 覆盖范围

- 文件树 1000 / 2000 / 8000 / 10000 个展开行：每帧耗时、分配、Outline 行数；断言 1000 到 10000 行的每帧分配不超过 1.2 倍，屏幕外的行没被建。
- 搜索结果替换 10000 行的目录树后只建可见行。
- 侧栏历史会话 80 条与 2000 条：仅构建视口内行，搜索覆盖完整工作区会话；选择菜单继续最多显示 80 条。
- 文件树交互：点击展开目录并选中该行，Home / End / 上下键移动选中行，回车和左右键收合展开，Ctrl+C 复制选中行的文件而不复制目录。
- 懒加载规则：没展开的目录没有子项列表但保留箭头，文件没有子项，展开才去读。
- 行的样式：23 像素行高、同一行距、选中行用面板底色上的淡色而不是列表的 accent 填充、文件名在 4 + 16 每级缩进加 16 箭头加 2 间隔之后。

## 做法与边界

源码在 `tests/explorer/desktop/`，带 `ally_explorer` build tag。`run.py` 用 `go test -overlay` 把它们挂到 `desktop` 包里跑，仓库里的 `desktop/` 不会被写入，临时 overlay 文件跑完即删。

- 时间只是记录，不断言：机器负载会抖；真正守回归的是分配次数和 Outline 行数。
- 离屏构建、布局和软件绘制，不含 GPU 帧时间；不开真实窗口，所以不测点击文件后读取编辑器（那条路径要窗口）。
- 只使用临时目录和合成数据，不读写真实会话、配置或用户文件。
