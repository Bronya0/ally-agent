# Code Graph Skill

`CODEGRAPH.md` 是可选的项目导航，帮助后续代理快速找到主要功能的入口。源码是事实来源；地图可能过期，编辑前仍需核实。

## 维护范围

- 用户要求生成且文件不存在时创建；普通编码任务不主动创建。
- 已有地图只在模块新增、入口迁移、职责变化使导航失真时增量更新；局部修复、参数调整、测试新增不要求更新。
- 用户要求精简或重写时可重组，否则只修改受影响条目。
- 不要求覆盖每个代码文件、测试或平台分叉，不枚举全部符号，不按文件数量强制派子代理。

## 内容与预算

全文 UTF-8 编码 **不超过 8192 字节（8 KiB，含标题与空白）**，与 Ally 的自动注入预算一致。优先控制在 4–6 KiB；字节预算不是字符数或行数。大型项目按模块归并，详细资料用文档路径指引，避免把设计说明搬进地图。

保留以下三节，项目很小时可以缩短：

1. `## 功能 → 文件速查表`：选择常用功能，两列「想找什么 / 去哪里」，给出工作区相对路径，必要时附 1–2 个入口符号。最有用的条目放前面。
2. `## 核心调用流`：几行描述入口、主要分发点、结果去向，只写主干。
3. `## 模块职责`：按主要目录或前缀分组，用一句话解释职责；构建入口与详细文档也可在此给出路径。

H1 使用 `# Code Graph: <project-name> — 功能导航`；开头简述用途与可能过期。语言跟随项目，所有路径相对工作区。规范与避坑留在 `AGENTS.md` / `LESSONS.md`，不复制实现细节、配置数值、修复历史或完整测试清单。

## 工作方式

先读取现有地图并查看项目主要目录，再针对需要新增或变更的导航项查找源码入口。无需通读或逐文件分析整个仓库；没有证据的职责不写入。

已有文件先 `read` 获取 version，再用 `edit` 修改；缺失时用 `create`。写后回读，检查路径和关键符号仍存在、主链路与源码一致，并测量 UTF-8 字节数。超过预算时合并次要条目、移除细节，直到全文可完整注入；不要依靠运行时截断。保持文件以换行结束。
